## 概要

ティアーズ オブ ザ キングダムの攻略マップ（祠・洞窟・コログ・ボス・影の像など41種類と地名チェックを1つの地図に載せている）。ビルド工程のない静的サイトで、
`dancerksk307/dancerksk307.github.io` リポジトリの `tok_wiki/` フォルダとして GitHub Pages で公開する
（https://dancerksk307.github.io/tok_wiki/）。このフォルダ自体は git 管理下にない。

## コマンド

```
node --test tests/                                   # 全テスト
node --test --test-name-pattern="衝突" tests/        # 名前で絞って1件だけ
node --test tests/pins.test.js                       # ピンデータの検査だけ（件数・id の重なり・洞窟と同名のピン）
```

画面確認は `index.html` を直接開けばよい（`file://` でも GitHub API の読み込みは通る）。

## 全体の作り

### 地図は外部の圧縮済みツールに任せている

`index.html` は、GameWith の地図ツール
（`article_maptool-3.0.0.zelda.min.js`、jQuery プラグイン `$.fn.leafletArticleMapToolV3`）を元サイトから直接読み込み、
ページ内の `window._mapDatas` / `window._typeDatas` / `var data = [...]`（ピン）を渡すだけ。ツール本体は改造できない。
そのため次の制約がある。

- `#article-body` と `#RenderMap` の id は変えない（ツールが幅の判定や CSS で依存している）。
- **ピンの種類名（`type`）でツールの動きが決まる**。吹き出しに何を出すか（名前・画像・記事リンク・チェック欄）は
  ツール内の `switch(type)` で固定されており、独自の種類名を作ると吹き出し自体が出ない。既存の種類名から選ぶこと。
- 種類 `cave` は「同じ `name` のピンを1つのチェックにまとめる」特別扱いがある。進捗の分母はピン数のままなので、
  入口が複数ある洞窟の名前に（1）（2）…を付けて、あえて別名にしている。
  このまとめ方は **種類を問わず「cave と同じ名前のピン」の id を cave 側の id に書き換える**。
  他の種類に洞窟と同じ名前のピンを足すと id がぶつかる（元の祠マップにあった種類 `hokora-cave` の31ピンは、これに当たるため載せていない）。
- リセットはツールが起動時に `.js-check-reset-all` へ処理を付ける（確認文言は `data-confirm`）。
  このボタンは `drawer.js` がサイドメニューの一番下に作るので、ツール起動より前に DOM に存在している必要がある。
- 吹き出しの「取得済み／未取得」の文言は `#RenderMap` の `data-pin-checked` / `data-pin-unchecked` で変えられる。
  全種類で1つの文言しか持てないので、祠にも洞窟にも合う「チェック済み／未チェック」にしている。
- 種類のON/OFFはツールが保存しない。開くたびに起動オプションの `defaultOffTypes` の状態に戻る。
  そこで `index.html` の `rememberShownTypes` が、ONの種類をこのブラウザに覚え（localStorage `TotkShownTypes`。GitHub には保存しない。利用者の判断）、
  次に開いたときは `loadShownTypes` でそれを `defaultOffTypes` に使う。覚えたものが無いとき（初めて開いたとき）は `DEFAULT_ON_TYPES`。
  チェック欄の change で覚えるが、「全てOFF」は change が起きないので、ボタンを押した後にも覚える。
- 進捗の数字はツールが入れる。画面内の `.w-achievement-count`（チェック数）と `.w-achievement-total-count`（総数）を、
  `data-types` の種類で数えて書き換える。☰ の進捗一覧（`drawer.js`）はこの仕組みに乗っているだけ。
- 検索は、選んだピンへ地図を動かして吹き出しを開くだけで、種類のON/OFFは変えない。
  `index.html` の `showTypeOnSearch` が、選んだピンの種類をONにする処理を足している。
  検索の一覧は `name`（無ければ `label`）で作られる。対象の種類は `SEARCH_TYPES`。
- 地図は空島・地上・地底の3つ（`window._mapDatas`）。元ページには `mapId` が「ダミー」のピンが混ざることがあり、
  どの地図にも出ないのに検索の一覧には出るので、載せない。
- 地図は画面いっぱい（上部バーは無い）。ツールの「全画面 ON/OFF」は、地図を画面いっぱいに広げるだけの仕組みなので、
  最初からその配置にして、ボタンは出さない（起動オプション `enableFullScreen: false`）。
  高さはツールが起動オプションの `height`（`MAP_HEIGHT` = 100vh）を !important で書き込むので、
  `common.css` で `#RenderMap { height: 100dvh !important }` と上書きしている（スマホのアドレスバーの出入りに合わせるため）。

### 下メニュー（横7マスのマス目。menu-layout.js / index.html の DEFAULT_MENU_LAYOUT）

ツールの下メニュー（`.TotkSideMenu`）は「見出し付きの組」しか受け取れず、マスの位置や空きマスを指定できない。
そこで、ツールに全種類のボタンを作らせた後で、`menu-layout.js` の `apply` がボタンを自前のマス目（CSS grid、7列）へ移している。

- 並びのデータは `{ version: 2, rows: [[7マス分の項目名か null], ...], lines: [線を入れる段の番号] }`。**閉じていても2段見える**。
  `rows[0]` はお気に入りの段（どの地図でも閉じていても見える上の段。7マスとも自由に置ける）。
  `rows[1]` は地上の段、`rows[2]` は地底の段。閉じたときの下の段には、空島・地上なら地上の段、**地底なら地底の段が出る**
  （`apply` が `#RenderMap` の `d-map` 属性を見張って入れ替える。段は作り直さずに移すだけなので、ON/OFF の状態はそのまま）。
  左端は固定マスで並べ替えの対象外。`rows[1][0]` が「表示設定」（`_toggle`）、`rows[2][0]` が「全てOFF」（`_clear`）。
  **固定マスは入れ替えでも動かない**（表示設定は閉じたときの下の段の左端、全てOFF はその次の段の左端へ、入れ替えのたびに戻している）。
  `lines` の n は「上から n 段目の上に1pxの区切り線を引く」（場所で決まり、入れ替えても動かない）。カテゴリの見出しは出さず、この線だけで区切る。
- **お気に入りの段に何も置いていない間は、お気に入りの段（とその下の線）を出さず、閉じたときは1段だけ見せる**（`hasFavorites`）。
  お気に入りの段が無かったころの並び（version 1。`rows[0]` が地上の段）は、`normalize` が上に空のお気に入りの段を足して読み替えるので、
  そのままだと空の帯が出てしまうため。
- 初期配置は `index.html` の `DEFAULT_MENU_LAYOUT`。**下メニューに出す項目はこれに置いたものがすべて**（`MENU_ITEMS`）。
  利用者が保存した並びは `normalize` で今の項目に合わせて直してから使う（知らない項目は消し、置かれていない項目は4段目以降の空きマスへ足す。
  固定マスは何が保存されていても表示設定・全てOFF にし、そこにあった項目は空きマスへ移す。ほかの場所にある全てOFF は消す）。
- マス（`.totk-menu-cell`）は flex なので、`align-items: flex-start` で中身を縦に伸ばさないようにしている（伸ばすと全てOFF の丸いボタンが縦長に崩れる）。
- **影の像は、ボタン1つ（両手剣のボタン。名前は「影の像」）で3種類（片手剣・両手剣・槍）をまとめてON/OFFする**（`index.html` の `LINKED_TYPES`）。
  ピンの種類は3つのまま（ツールは、この3種類のピンを押したときだけ、出てくる武器の一覧を出すため）。
  片手剣・槍のボタンもツールに作らせ、マス目には置かず、見えない入れ物（`.totk-menu-hidden`）に入れて画面の中に残す
  （ツールは画面の中のチェック欄を見てピンを出し入れするので、外したままにすると出せなくなる）。
  両手剣のボタンを押すと `linkTypeSwitches` が残り2つのチェック欄を同じ状態にする。ボタンに直接付けた処理は、
  ツールが document に付けた処理より先に走るので、ツールはそろった状態でピンを出し入れする。
  武器名のプルダウンを出すかもこのチェック欄で決めるので、`linkTypeSwitches` は `setupWeaponFilter` より先に呼ぶ（同じボタンの処理は付けた順に走る）。
- ツールには、1組目＝お気に入りと地上の段の種類、2組目＝残りの種類とマス目に置かない種類（`toolGroups`）を渡す。組の分け方は見た目に関係しない。
  ボタンは作り直さず DOM ごと移すので、ツールが付けた処理（ON/OFF・スワイプ判定）はそのまま効く。
  移す前に `detach` で外す（入れ物ごと消すと jQuery がボタンに付いた処理まで消すため）。
- 開いたメニューの高さは、ツールの既定だと390pxで固定（起動オプションでは変えられない）。
  `index.html` の `fitMenuHeight` が、ツールの起動前にメニュー部品（`L.Control.SlideMenu`）の既定値を書き換えて中身に合わせている。
  閉じているときに隠れている分は `menuHideHeight`（閉じていても見える2段より下の段×48px＋線×8px）。**必ず8の倍数になるようにしている**
  （ツールはメニューを8pxずつ動かし、ちょうど0にならないと開閉が止まらない）。段や線の高さを変えるときは、`common.css` の
  `.totk-menu-row`（48px）・`.totk-menu-line`（余白込み8px）と `menu-layout.js` の `ROW_HEIGHT` / `LINE_HEIGHT` を一緒に変える。
  ツールは閉じたときに1段分（`showHeight` 62px）だけ見せる作りなので、お気に入りの段（とその下の線）の分（`menuShowExtraHeight`）をメニューの高さに足す。
  この分は CSS の変数 `--totk-menu-extra` にも入れ、メニューの上に並ぶ部品と検索の候補を、その分だけ持ち上げている。
  ツールはメニューの背景の高さも400pxで固定しているので、`common.css` で中身に合わせて伸ばしている（8段にすると400pxを超える）。
- 「表示設定」「全てOFF」は、ツールが段の外に絶対位置で置くが、2つともマスの中へ移している（`.totk-in-grid`）。
  ツールは開いている間「表示設定」を薄くするが、押せないように見えるので、これも打ち消して常に同じ見た目にしている。
- **閉じたメニューのボタンの下に余白（`common.css` の `--totk-menu-space`、いまは24px）を空けている**。
  画面の下端から持ち上げて押しやすくするため（ホーム画面に追加したアプリでは、下端がスマホ本体の操作と重なる）。
  この値は、1段目の下の余白・メニューの高さ（`fitMenuHeight` が読む）・メニューの上に並ぶ部品の位置・
  検索の候補の位置に効く。変えるときは CSS の変数1つだけを変えればよい。
- 組を2つ以上渡すと、ツールがメニュー全体にスワイプ用の処理を付け、ボタン（`label`）以外へのタッチを打ち消す。
  例外は、押した場所の親（`offsetParent`）が `_toggle-btn` か `_clear-btn` のとき。
  そのため、マスへ移した「表示設定」「全てOFF」は `position: relative` のままにしている（static にすると親が変わり、スマホで押せなくなる）。
  メニューの中に独自のボタンを足しても、スマホでは押せない。

### 下メニューの並べ替え画面（menu-layout.js の openEditor）

サイドメニューの「下メニューの並べ替え」で、同じページの上に全画面で開く（別ページにすると種類のデータを2か所に持つことになるため）。
説明文と見出しの × ボタンは、利用者の要望で置いていない（閉じるのは下の「やめる」）。
閉じていても見える段は、背景の色で分けている（お気に入りは灰、地上の段は緑、地底の段は紫）。固定マスには鍵の印を付ける。

- アイコンは Pointer Events で動かす（指もマウスも同じ処理。ライブラリは使わない）。空きマスへは移動、他の項目の上では入れ替え（`moveItem`）。
  今の段の下に空の段を1つ出し、そこへ置くと段が増える（8段まで）。小さい画面では縦に収まらないので、ドラッグ中に上下の端へ近づけるとスクロールする。
- 段と段の間を押すと区切り線を付け外しする（`toggleLine`）。
- 「保存」で並びを GitHub に保存し、ページを読み直して反映する（ツールの下メニューは作り直せないため）。
- 並びの保存先は、`save-data` ブランチの `tok_wiki/data/menu-layout.json`（`config.js` の `layoutPath`）。
  **チェックのデータ（`save.json`）とはファイルを分けている**。並びの保存がチェックのデータに触れないようにするため。
  並びは「保存」を押したときだけ変わるので、チェックのような差分の重ね合わせはせず、最後に保存したもので丸ごと置き換える（`save.js` の `createFileStore`）。
  ブラウザ内にも控え（localStorage `TotkMenuLayout`）を持ち、起動時に GitHub から読めないときはそれを、それも無ければ初期配置を使う。
  トークンが無いときは控えにだけ保存する（GitHub に並びがあれば、次に開いたときはそちらが使われる）。

### 地名チェック（location-pins.js）

完璧版にある「地名の印」（地名223か所。タップ1回でチェック）を、下メニューの「地名」で出し入れする。
「地名」は、種類データの `area`（ピンが0件の種類）をメニューに入れて、そのチェック欄を使っている（ボタンの画像は `_typeDatas` で差し替え）。

- **地図ツールの `.LocationPin` は使わない**。ツールはこの部品用にチェック状態の控えをもう1つ持ち、書き込むたびにその控えで
  `ZeldaTotkMap` を丸ごと上書きする。祠などを先にチェックしていると、そのチェックが消え、消えた状態が GitHub にも保存されてしまう。
- 自前の部品は、毎回 localStorage を読み直して1件だけ変えて書き、書いた後にツールの入口 `window.loadLocalStrageByLeafletArticleMapTool` で
  ツール側の控えも読み直させる。ツールの地図は外から取れないので、起動前に `L.Map.addInitHook` でつかまえている。
- 印を出す・隠すのはツールの CSS（`#RenderMap .location-pin`）と `common.css`。ツールは拡大1〜3段階で印を !important で隠すので、
  印は拡大4段階目から出る（完璧版と同じ）。引いた地図で「地名」をONにしたときは、拡大するようお知らせを出す（`noticeAreaZoom`）。
- 地名の数はツールが数えないので、サイドメニューの進捗の「地名」の数はこの部品が入れる（`.totk-area-count` / `.totk-area-total`）。

### 影の像の武器名プルダウン（index.html の setupWeaponFilter）

武器の一覧はツールの部品（`.ShadowWeaponFilter()`）が作る。作られた後で、検索欄のすぐ上へ移す。影の像のどれかがONのときだけ出す。

- ツールの絞り込みは、残す像に `display: block` を直接書き込むので、メニューで影の像をOFFにしても像が消えなくなる。
  ツールが書き込んだ後（選んだとき・地図を切り替えたとき）に書き直し、残す像は書き込みを消して（ON/OFF と地図はツールの CSS に任せる）、
  選んだ武器が出ない像だけを隠している。
- この部品は付けた時点で影の像のメニューボタンを隠すので、`.TotkSideMenu` より前につないでいる（後につなぐとボタンが消える）。
- 検索欄と同じクラス（`leaflet-keyword-search-ui`）を使うので、`moveControlsToBottom` は検索の入力欄（`#JsWKSUPinSelect`）を目印に検索欄を探す。

### 操作部品の置き場所（index.html の moveControlsToBottom / common.css）

ツールは、拡大縮小を左上、検索欄を右上に置く（場所は選べない）。指が届きやすいよう、作られた後で下側へ移している。

**地図の中心は、画面の上から25%の位置として扱っている**（`index.html` の `liftMapCenter`。`MAP_FOCUS_RATIO`）。
画面の下側は部品と下メニューで隠れるが、ツールは「地図の端が画面の端より内側に入らない」範囲（`maxBounds`）でしか地図を動かせず、
引いた地図で地図の下の方が部品の裏から出てこなかったため。

- ツールが地図ごとに呼ぶ `setMaxBounds` を包み、範囲を下へ「画面の高さの半分」だけ広げる。地図の下端を画面の真ん中まで持ち上げられ、
  地図が画面より小さいときは上から25%の位置に置かれる。範囲は地図上の距離で持つので、拡大率が変わるたび（`zoomend`）と画面の大きさが変わるたびに計算し直す。
- ＋−ボタン（`map.zoomIn` / `zoomOut`）は、上から25%の点を動かさずに拡大縮小する（`setZoomAround`）。指2本の拡大は指の位置が中心のまま。
- 検索で選んだピンへの移動と、開いたときの位置は、ツールのまま（画面の真ん中）。
- 地図はツールの外から取れないので、起動前に `L.Map.addInitHook` でつかまえている。
- 確認用のヘッドレス Chrome では、拡大の動き（アニメーション）が終わらず拡大率が変わらないことがある。確かめるときは `map.options.zoomAnimation = false` にする。
サイドメニューを開く ☰（`drawer.js` が作る `.totk-menu-button`）とメモ（`memo.js` が作る `.totk-memo-button`）も、ここで地図の中へ入れる。

- **下側の部品の左右は、画面の幅で入れ替わる**。スマホ幅（`#article-body` が450px以下）では「左下に境界線・地図の切り替え、右下に進捗」、
  PC幅ではその逆。角を決め打ちにすると片方で崩れるので、「地図の切り替えの上」「進捗（隠している）の隣」を目印にして移し、CSS も左右両方の角に書いている。
  直したら両方の幅で確かめる。
- 拡大縮小・☰・メモは、地図の切り替えと同じ列の上へ（上から拡大縮小・☰・メモ）入れる。
  チェック済みを薄くするボタン（`setupHideChecked`）と境界線のボタン（`setupBorderButton`）は、メモと同じ入れ物に入れて横に並べる
  （`.totk-button-row`。右の角では地図の中央寄りに来るよう並びを逆にする）。
  ☰ とメモはツールの部品ではないので、部品の並べ方に乗る入れ物（`.leaflet-control.totk-button-control`）に入れ、
  `L.DomEvent.disableClickPropagation` で、押したときに地図が動かないようにしている。
  ☰ とメモは地図の中へ移すまで見えない（`common.css`）。地図ツールの起動に失敗すると ☰ もメモも出ない点に注意。
- **地図の上の進捗（n/152）と、ツールの境界線の切り替え（有／無）は出さない**（利用者の要望。`common.css` で隠す）。
  - 進捗は、検索欄を置く角の目印にだけ使う。☰ の進捗一覧の数は、ツールがこの部品とは別に数えて入れるので影響しない。
  - 境界線は、目のボタンの横の四角いボタン（`setupBorderButton`）で切り替える。ボタンから、隠したツールの「有／無」の選択肢を押す
    （ツールは選択肢の onchange で地図を描き直す）。境界線を出している間はボタンを青にする。
  - ツールは地上の地図にしか境界線を持たず、地図を切り替えるたびに「有／無」を jQuery の `show()` / `hide()` で出し入れする。
    `show()` は display を直接書き込むので、隠す指定は `!important`。ボタンも地上のときだけ出す（`#RenderMap` の `d-map` を見張る）。
- 検索欄は `totk-search` クラスを付けて、進捗のある角へ入れる。その角に `totk-bottom-row` クラスを付けて横並び（flex）にしている。
  角の幅を決める `106px` は、反対側の「地図の切り替え」の幅（96px）から決めた値。検索欄は残りの幅に合わせて縮む。
- 拡大縮小・☰・メモ・地図の切り替え（空島・地上・地底）は、スマホで押しやすいよう、ツールの標準の1.5倍にしている（`common.css`）。
  地図の切り替えの幅（96px）を変えたら、`.totk-bottom-row` の `106px` も合わせる。
- 検索欄を押すと出る入力欄と候補の一覧（`#RenderMap > .select2-container--open`）は、検索欄のすぐ上から上方向に出す。
  ツールは「欄の下に出す」位置を `top` で直接書き込むので、そのままだと地図の下からはみ出して見えない。
  `top` を打ち消して地図の下端からの距離（`bottom: 111px` ＋メニューの余白）で固定し、中身を上下逆（入力欄が下、候補が上）に並べている。
  111px は検索欄の高さと下の余白から決めた値なので、検索欄の位置や高さを変えたら合わせて変える。
- ツールの「進捗を右下に置くか左下に置くか」の判定は、起動時に右下の角が空かどうかで決まる。部品を移すのは必ず起動の後にする。

### ピンの見た目（common.css）

- チェック済みのピンは、ツールの「透明度0.5＋灰色」が薄すぎて見つけにくいので、灰色をやめて透明度0.8にし、
  右上に赤丸（直径4px、白の1pxのふち）を付けている（ツールの指定は `opacity: 1; filter: none` で打ち消す）。**赤丸は透けさせない**。
  ピンはふつう画像（`img`）で `::after` が使えないので、赤丸は背景に描いている（絵より下に描かれるので、絵に重なった部分は隠れる）。
  `opacity` は背景の赤丸まで透けさせるので、画像のピンはマスク（`mask`）で「赤丸の中は1、残りは0.8」にしている。
  マスクの外は消えるので、赤丸はピンの20pxの中に収めている。
  大きく拡大して名前が出ているピンは、ツールが「絵と名前」の箱（div）に作り替え、名前が箱の外に出るのでマスクは使えない。中の絵と名前だけを0.8にしている。
  丸の位置はピンの大きさ20px（ツールの既定。種類データに `size` があると変わる）から決めた値で、
  `size` を持つ種類が無いことを `tests/pins.test.js` で確かめている。
- 夜光イワロックの色（下）はチェック済みには付けない。`filter` は赤丸にもかかり、赤丸まで青緑になるため。
- **チェック済みのピンは、メモの横の目のボタン（`index.html` の `setupHideChecked`）で、全種類まとめてもっと薄く（透明度0.3）できる**。
  消さずに薄くするのは、利用者の要望（どこをチェックしたかも見えるように）。赤丸は透けさせない。
  `#RenderMap` に `totk-hide-checked` を付け外しし、薄くするのは CSS（画像のピンはマスクの画像を 0.3 のものに替える）。
  クラス名と保存のキーは、隠す作りだったころの名前のまま。
  地名の印はツールの `is-checked` が付かない（付けるとツールの見た目の指定がかかる）ので、`location-pins.js` がチェック済みに `totk-area-checked` を付けている。
  ツールの種類のON/OFFと違い、開き直しても前の状態のままにするため、このブラウザに覚えておく（localStorage `TotkHideChecked`。GitHub には保存しない）。
- 夜光イワロックは、ツールではふつうのイワロックと同じ白いアイコン。`index.html` の `markNightTalus` が、label が「夜光」で始まるピンに
  `totk-night` を付け、`filter` で青緑にしてほんのり光らせている（白いアイコンは色相を回しても色が付かないので、いったん sepia をかける）。
  ガチロック（青）・マグロック（赤）・希少（金）は、元から色違いのアイコン（`overrideIcon`）がある。

### 地図の上のお知らせ（index.html の showNotice）

`showNotice`（`common.css` の `.totk-notice`）で、地図の上に短いお知らせを出す。いまは次の2つ。
- 地名の印に拡大が要ること（`noticeAreaZoom`）
- 今の地図にピンが無い種類をONにしたとき、どの地図にあるか（`noticeOtherMap`）。賢者の遺志・古びた地図はピンが空島にしか無く、
  地上でONにしても何も出ないので、壊れていると思われたため
地図の部品より手前に重ねるため `#RenderMap` の中に置いている。
同時にONにできる種類の数の上限（5種類）は、利用者の要望で無くした。
メニューの中のクリックは Leaflet が外へ伝えないので、ボタンに処理を足すときは `document` ではなくボタン1つずつに付ける。

### チェックデータの保存（save.js）

ツールはチェック状態を localStorage のキー `ZeldaTotkMap`（`{"3001":true,...}`）にしか読み書きしない。
すべての種類のチェックがこの1データに入る。`save.js` はツールに触れずに前後へ同期を挟む。

1. 起動前に GitHub Contents API から json を取り、localStorage に入れる。`index.html` は `TotkSave.ready` を待ってからツールを起動する。
2. `Storage.prototype.setItem/removeItem` を包んで `ZeldaTotkMap` への書き込みを検知し、3秒後にまとめて `PUT`（1保存＝1コミット）。
3. 最後に同期した状態を `ZeldaTotkMap_base` に持ち、**丸ごと上書きせず「base との差分」だけを最新に重ねる**。
   他の端末・タブとの衝突（409/422）や、送る前に閉じた変更の再送はこの差分方式で解決している。
   base が無い（そのブラウザで初めて）ときは GitHub 側を正とし、元からあるブラウザ内データは引き継がない。

`save.js` は `createSync`（通信・保存先を外から渡せる本体。テスト対象）と `start`（ブラウザ用の組み立て）に分かれた UMD。
下メニューの並びとメモは、それぞれ別のファイルに `createFileStore` で読み書きする（上の「並べ替え画面」と下の「メモ」を参照）。
`createSync` とは別のもので、チェックのファイルには触れない。
保存先は `config.js`。公開用の master ではなく `save-data` ブランチに保存している（master だと保存のたびに Pages の再公開が走るため）。
ブランチが無ければ初回保存時に既定ブランチから自動で作る。

GitHub のトークンはコードに書かない。メニューから入力し、そのブラウザの localStorage（`TotkGithubToken`）にだけ置く。

### サイドメニュー（drawer.js / common.css）

`drawer.js` が ☰ ボタンと、ドロワー（進捗・下メニューの並べ替え・保存設定・保存状態・リセット）を body 先頭に差し込み、
`TotkSave.start()` を呼ぶ。読み込み順は `config.js` → `save.js` → `drawer.js` → `location-pins.js` → `menu-layout.js` → `memo.js` → `index.html` の起動スクリプト。
クラス名はツールの CSS とぶつからないよう `totk-` で始める。

### メモ（memo.js / common.css）

地図の左下の鉛筆のボタン（☰ の下）で、画面の下半分に開く（上の地図はそのまま使える。利用者の要望）。
下に「閉じる」「編集」「保存」。「編集」で読む画面が入力欄に変わる。編集中も下半分のまま
（利用者の要望。スマホのキーボードでどう見えるかは利用者が確かめる）。
開いている間はメモのボタンが見えていても2枚目は開かない。

- 中身はプレーンテキストで、`save-data` ブランチの `tok_wiki/data/memo.txt`（`config.js` の `memoPath`）に保存する。
  `createFileStore` の `format: 'text'` で、**書いたとおりの文字のまま**保存・読み込みする（空白・空行・タブ・末尾の改行の有無も変えない）。
  読む画面は CSS の `white-space: pre-wrap` でそのまま表示する。
- 開くたびに GitHub の最新を読む（他の端末で書いた分も見えるように）。読み終わるまでは「編集」を押せない
  （古い内容から書き始めると、保存したときに他の端末で書いた分を上書きしてしまうため）。
  チェックのような差分の重ね合わせはしないので、2つの端末で同時に編集すると、後から保存した方が残る。
- ブラウザ内にも控え（localStorage `TotkMemo`）を持つ。GitHub から読めないときはそれを出し、トークンが無いときはそれにだけ保存する。
- 保存していない変更があるときに「閉じる」を押すと、確かめる。

### ホーム画面に追加（PWA: manifest.webmanifest / sw.js / icons/）

- `manifest.webmanifest` がアプリ名・アイコン・色、`display: standalone`（アドレスバー無し）を決める。
  iPhone はアイコンと名前を manifest ではなく `index.html` の `apple-touch-icon` / `apple-mobile-web-app-title` から取る。
- `sw.js`（サービスワーカー）は、**このフォルダ（`tok_wiki/`）のファイルだけ**を扱う。いつもはネットから取り、取れないときだけ前回の控えを返す。
  **GitHub API（保存データ）・地図画像・地図ツールなど外のサイトの通信には関わらない**。保存データを控えから返すとチェックが巻き戻るため。
  この決まりは `tests/pwa.test.js` で確かめている。sw.js を直したら必ず通す。
- 控えの名前は `totk-map-` で始める。入れ替えのときに消すのはこの名前の古い控えだけ
  （同じドメイン `dancerksk307.github.io` の他のページの控えを消さないため）。
- いつもネットから取る作りなので、ファイルを更新しても控えの名前（`CACHE_NAME`）を変える必要はない。
  sw.js 自体を変えたときは、ブラウザが次に開いたときに入れ替わる。
- サービスワーカーは `file://` では動かない（`index.html` で http/https のときだけ登録している）。
  画面で確かめるときは、ローカルに配信サーバーを立てて `/tok_wiki/` の下で開く。
  なお、確認用のヘッドレス Chrome では Cache Storage が内部エラーで使えなかった（控えの動きはテストで確かめている）。
- アイコン（`icons/`）は、利用者から渡された壁紙の画像（678×545px。Reddit の投稿 r/tearsofthekingdom の 1333tk8 のもの）から、
  中央の紋章を正方形（555px）に切り抜いて作った。
  - 切り抜く範囲は、明るい緑の部分（紋章の線）の外枠を求め、その中心から1辺の3%ずつ余白を足して決めた。
    紋章の上端が画像の端ぎりぎりのため、上の8pxははみ出していて、元画像の四隅の色（黒）で埋めている。
  - `icon-192.png` `icon-512.png` `apple-touch-icon.png`（180px）は切り抜いた正方形をそのまま縮小、
    `icon-512-maskable.png` は Android が丸や角丸に切り抜いても欠けないよう、図柄を中心から半径40%の内側（80%の大きさ）に縮め、
    四角い縁が見えないよう外側をぼかしながら丸く切り抜いて黒の背景に重ねている。
    スプラッシュ画面（起動中の画面）の色 `background_color` も黒にしている。
  - 作り直すときは、元画像を Chrome の canvas で描いて PNG に書き出す（このPCには画像ツールが無い）。

## ピンの種類を追加するとき

1. `index.html` の `var data` にピンを足し、`DEFAULT_MENU_LAYOUT` の空きマスに種類名を足す（既存の種類名から選ぶ。上の制約を参照）。
   初めて開いたときに出すなら `DEFAULT_ON_TYPES` に（ON/OFFを覚えている利用者には、新しい種類はOFFで出る）、名前で探せるようにするなら `SEARCH_TYPES` にも足す。
   並びを保存済みの利用者の下メニューには、2段目以降の空きマスに自動で足される。
2. 開いた状態の下メニューをスマホ幅の画面で確かめる。
3. チェック欄がある種類なら、`drawer.js` の `PROGRESS_GROUPS` に1行足す。
4. ピンの `id` は全体で重ならないようにする（保存データが共通のため）。GameWith 由来は5桁以下、Game8 由来は7桁。
5. `tests/pins.test.js` の内訳と、`README.md` の一覧を更新する。

完璧版（https://gamewith.jp/zelda-totk/article/show/398189）は、ほかの GameWith の地図ページのピンをすべて含む。
今の地図と同じ id のピンは、id・種類・名前が一致していた（取り込んだときに確認）。洞窟・井戸・防具は載せていない（理由は `index.html` のピンデータのコメント）。
取り込み前のピンは `tests/fixtures/pins-v1.json` に控えてあり、id・種類・名前が変わっていないことをテストで確かめている（今までのチェックが外れないように）。

GameWith のページはピンデータをそのまま抜き出せる。Game8 のページは地図の仕組みが別物（React 製、チェックは Game8 のサーバー保存）なので、
`https://game8.jp/api/tool_structural_mappings/{id}.json` のデータを GameWith の形式に変換して載せる。
座標は地図ごとにずれるため、両サイトに共通する祠・鳥望台を名前で突き合わせて1次式を求めて変換した（`index.html` のピンデータのコメント参照）。

## 編集時の注意

- 全ファイル LF・UTF-8（リポジトリに入っている状態）。このPCは git の autocrlf が有効なので、ブランチの切り替えやマージの後は
  手元のファイルだけ CRLF になる。コミットすれば LF に戻るので、手元の改行をわざわざ変換しない。
  いまの改行は `git ls-files --eol` で見る（左がリポジトリ内、右が手元）。Git Bash の `grep` は CR を無視するので確認に使えない。
- `index.html` はピンデータで1行が長く、行数も多い（約66万バイト）。
  スクリプトで置換するときはバイト列のまま行い、改行コードを変えない。
- ピンデータを書き換えたら、件数と種類ごとの内訳を数えて確かめる（`tests/pins.test.js` が内訳を検査している）。
